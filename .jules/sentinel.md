## 2024-11-26 - [Arbitrary Meta Update via Unvalidated POST Variable]
**Vulnerability:** In `includes/Admin/Ajax_Handler.php`, the `ajax_sort_rows` method fetched the `$field_key` from user-supplied `$_POST` and ultimately used it as the meta key in `update_post_meta`. Since there was no server-side validation to guarantee that the `field_key` corresponded to a legitimate ACF field (or even an ACF field of the correct type), an authenticated user with edit post privileges could craft a request and arbitrary update any meta key for a specific post.
**Learning:** This vulnerability existed because the code trusted the client to send a valid `$field_key` specifically for an ACF repeater field, omitting server-side checks for the field's existence, context, and expected field type before performing destructive or updating operations. This is akin to an IDOR where the object reference is an arbitrary meta key.
**Prevention:** Always validate all user-supplied keys and references on the server side against a trusted source (e.g., using `acf_get_field()` and verifying the field type) before using them as keys in database update operations. Never trust client-supplied input for sensitive identifiers or field names.
